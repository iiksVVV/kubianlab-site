# DESIGN BRIEF: редизайн сайта «КубианЛаб — умная тележка»

Ты выступаешь как опытный продуктовый дизайнер + верстальщик. Твоя задача: довести существующий статический сайт проекта до красивого, целостного, «дорого» выглядящего состояния, сохранив все фактические данные и обязательные по договору элементы. Это сайт технологического стартапа, а не корпоративный лендинг: сдержанно, современно, без перегруза.

2. В разделе «Контакты» в самом низу остаётся логотип ФСИ (`assets/fasie-logo-candidate.png`).
3. Сайт остаётся статикой без сборки и без внешних CDN/шрифтов с CDN (стили и графика — локально). JS — минимальный или отсутствует.

7. Мобильная адаптивность обязательна (брейкпоинты ~900px и ~560px уже есть, можно улучшить).
8. Не превращать в перегруженный лендинг: без pop-up, cookie-баннеров, слайдеров-каруселей, анимационных библиотек. Максимум легкий scroll-эффект, если он не мешает.

## 3. Факты проекта (использовать как есть, править стиль, не содержание)

- Продукт: «КубианЛаб» — программно-аппаратный комплекс: мобильная сборочная тележка для складов и дарксторов.
- Что делает: один сборщик параллельно собирает несколько заказов; каждый товар сканируется и проверяется датчиками при размещении в контейнер; этикетка печатается на тележке; склад перестраивать не нужно.
- Архитектура: двухуровневая — Android-устройство с приложением (верхний уровень) ↔ BLE ↔ микроконтроллер STM32 (нижний уровень) → датчики: лидар X-WPFTB-V2.6.2, инфракрасные датчики FC-51, тензодатчики 15 кг (по 4 на контейнер), световая индикация; сканер штрихкодов/QR; термопринтер этикеток (Godex, EZPL).
- Корпус: преимущественно алюминий, отдельные элементы и крепления — 3D-печать; совместим со стандартными складскими корзинами.
- Пилот: реальный склад, февраль 2026, собрано около 120 заказов, включая параллельную сборку.
- Внутренний хронометраж: сокращение времени сборки примерно на 17% (самостоятельный замер без независимой проверки, уточняется на пилотах — формулировку с этой оговоркой сохранить).

## 7. Ограничения по медиа

- Не вставлять видео/фото больше: фото ≤ 300 КБ каждое, видео ≤ 1 МБ суммарно на страницу (можно перекодировать ffmpeg: 480p, H.264, CRF 28-30, без звука).
- Не тянуть внешние CDN (шрифты/иконки/библиотеки). Всё локально в `assets/`.
- Не увеличивать суммарный вес страницы заметно (сейчас ~1,6 МБ). Цель: остаться примерно в тех же пределах.
- Схему архитектуры можно перерисовать красиво (SVG inline допустим), но фактический состав не менять: Android-приложение ↔ BLE ↔ STM32 → LiDAR X-WPFTB-V2.6.2 / ИК FC-51 / тензодатчики 15 кг ×4 на контейнер / индикация; сканер (режим клавиатуры); принтер Godex (EZPL); API внешних систем (кэш каталога).

## 8. Процесс работы и правила

1. Работать в папке `site/`. Правки коммитить локально: `git add -A && git commit -m "..."`.
2. Пуш в `origin/main` (GitHub Pages) выполняется ТОЛЬКО после подтверждения владельца (авторизация gh уже настроена на аккаунт iiksVVV).
3. Проверяй локально: `python3 -m http.server 8080`, смотри на десктопе и в мобильном разрешении (DevTools 375px и 768px).
4. Не менять URL-структуру и имя главной страницы (index.html) — ссылки в отчётности уже используют корень сайта.
5. Обязательный текст ФСИ проверять grep'ом после правок: `grep -c "Проект реализован при поддержке Фонда содействия инновациям" index.html` (должно быть ≥ 1 на главной + футер).
6. Проверка дефисов: в текстах страницы не должно быть символа «—» (U+2014): `grep -n "—" index.html` должен быть пуст.
7. Секреты: проверять, что в HTML/CSS/assets нет токенов/ключей (`grep -ri "token\\|secret\\|api_key" .`).
